# 토정비결·주역 원전 기반 구현 조사

> 조사 기준일: 2026-07-30
>
> 목적: Oh My Saju에 넣을 수 있는 **결정적이고 버전이 고정된 계산 계약**을
> 정한다. 점술의 사실성이나 예언의 효력을 입증하는 문서가 아니다.
>
> 출처 원칙: 고전 원문·공공기관 소장본·공식 카탈로그를 우선하고, 현대 서적과
> 오픈소스는 계산 예의 교차 검증에만 사용한다.

## 1. 결론

### 바로 구현 가능한 범위

1. `tojeong-number-144@1.0.0`
   - 음력 생월·생일, 해당 연도의 세는나이, 해당 연도 간지·월건·일진을 입력으로
     `상수 1..8 / 중수 1..6 / 하수 1..3`을 계산한다.
   - 결과는 `111..863` 가운데 정확히 144개인 코드 하나다.
   - 계산 중 사용한 큰달/작은달, 연·월·일 간지, 각 수표 항목과 나머지를 모두
     감사 필드로 반환한다.
2. `zhouyi-mechanics@1.0.0`
   - 효를 아래에서 위로 저장하고 `6/7/8/9`를 노음·소양·소음·노양으로 구분한다.
   - 삼전법과 주희식 시초법을 서로 다른 생성 profile로 제공한다.
   - 본괘, 동효, 변괘, 상괘·하괘, 주역 64괘의 통상 괘서와 한문 괘명을 계산한다.
3. `shaoyong-xiantian@1.0.0`과 `shuogua-houtian@1.0.0`
   - 선천·후천 배치를 별도 profile로 제공한다. 이것을 역사적으로 복희·문왕이
     직접 그린 도상이라고 단정하지 않는다.

### 바로 넣으면 안 되는 범위

- 현대 한국어 토정비결 풀이, 현대 번역 주역 괘·효사는 저작권이 별도로 있으므로
  복사하지 않는다.
- 토정비결 144개 점사에는 판본 차이와 착간이 확인된다. 출처가 섞인 “통합 정본”을
  만들지 않고 **한 소장본을 하나의 corpus version으로 고정**해야 한다.
- 점괘를 건강·재산·결혼 등의 실제 사건 확률이나 단일 길흉 점수로 바꾸는 공식은
  원전에서 검증되지 않는다. 계산 사실과 해석은 분리한다.

한국민족문화대백과사전은 토정비결이 생시를 제외한 연·월·일로 상·중·하 수를
만들며, 주역 64괘 가운데 48괘를 사용하고 16괘는 사용하지 않는다고 설명한다.
따라서 144개 토정 코드를 “주역의 서로 다른 144괘”라고 부르면 안 된다.
([한국민족문화대백과사전](https://encykorea.aks.ac.kr/Article/E0059207))

### 2.2 정확한 수표

류큐대학교 논문의 표 1(p. 201)을 그대로 계산 규칙으로 옮기면 다음과 같다. 각 간지의
수는 천간수와 해당 용도의 지지수를 더한다.

#### 공통 천간수

| 천간  |  수 |
| ----- | --: |
| 甲·己 |  10 |
| 乙·庚 |   9 |
| 丙·辛 |   8 |
| 丁·壬 |   7 |
| 戊·癸 |   6 |

#### 지지수

| 지지  | 태세수용 |      월건수용 | 일진수용 |
| ----- | -------: | ------------: | -------: |
| 巳·午 |        8 | 3(巳) / 8(午) |        6 |
| 寅·卯 |        9 | 6(寅) / 5(卯) |        7 |
| 亥·子 |       10 | 3(亥) / 8(子) |        8 |
| 申·酉 |       11 | 6(申) / 5(酉) |        9 |
| 辰·戌 |       12 |             4 |       10 |
| 丑·未 |       12 |             7 |       11 |

즉 용도별 함수는 다음과 같다.

```text
taese(ganzhi)  = stemNumber[stem] + taeseBranchNumber[branch]
wolgeon(ganzhi)= stemNumber[stem] + wolgeonBranchNumber[branch]
iljin(ganzhi)  = stemNumber[stem] + iljinBranchNumber[branch]
```

나머지가 0이면 제수 자체를 반환하는 함수를 먼저 고정한다.

```text
residue1ToN(value, n) = ((value - 1) mod n) + 1
```

### 2.3 `tojeong-number-144@1.0.0` 산식

현대 공개 예와 기관 문화대전의 설명을 교차 확인하면 월건과 일진은 출생 당시가
아니라 **운세 대상 연도의 같은 음력 생월·생일**에서 취한다.
([디지털미추홀구문화대전](https://michuhol.grandculture.net/michuhol/dir/GC04701722),
[공개 계산 예](https://www.yes24.com/product/goods/116992201#book_inside))

```text
upper =
  residue1ToN(
    countingAgeInTargetYear + taese(targetYearGanzhi),
    8
  )

middle =
  residue1ToN(
    daysInTargetYearLunarBirthMonth
      + wolgeon(targetYearLunarBirthMonthGanzhi),
    6
  )

lower =
  residue1ToN(
    lunarBirthDay
      + iljin(targetYearLunarBirthMonthAndDayGanzhi),
    3
  )

code = decimalDigits(upper, middle, lower)
```

필수 감사 입력·출력:

- 원 출생일의 양력/음력 구분과 음력으로 정규화한 월·일
- 대상 연도
- 대상 연도의 세는나이와 그 산출 방식
- 대상 연도 세차
- 대상 연도의 해당 음력월 일수와 월건
- 대상 연도의 해당 음력 월·일의 일진
- 세 수의 합계, 제수, 원 나머지와 `0 → 제수` 정규화
- 사용한 역법 dataset/version

### 2.4 독립 회귀 오라클

공개된 현대 서적 예시는 다음 숫자를 명시한다. 문장 해설은 저작권 대상이므로 test
fixture에는 숫자 사실만 기록한다.

```text
target year: 2023 癸卯
counting age: 31
lunar birth month/day: 3/8

taese(癸卯) = 6 + 9 = 15
upper = residue1ToN(31 + 15, 8) = 6

target lunar month 3 has 30 days
month ganzhi: 丙辰
wolgeon(丙辰) = 8 + 4 = 12
middle = residue1ToN(30 + 12, 6) = 6

day ganzhi at target lunar 3/8: 乙卯
iljin(乙卯) = 9 + 7 = 16
lower = residue1ToN(8 + 16, 3) = 3

expected code: 663
```

이 fixture는 역법 계층에서도 `2023년 해당 음력 3월=30일`, `월건=丙辰`,
`음력 3월 8일 일진=乙卯`를 각각 확인해야 한다. 최종 코드만 맞고 중간 근거가 다르면
통과시키지 않는다.

수표 자체의 작은 단위 오라클:

```text
taese(甲午)  = 10 + 8 = 18
wolgeon(丙辰)=  8 + 4 = 12
iljin(乙卯)  =  9 + 7 = 16

residue1ToN(56, 8) = 8
residue1ToN(42, 6) = 6
residue1ToN(24, 3) = 3
```

첫 번째 값 `甲午 → 18`은 류큐대학교 논문의 표 아래 저자 계산 예이기도 하다.

### 2.5 판본·입력에서 확정되지 않은 것

다음은 현재 확보한 원전에서 하나의 규칙으로 확정할 수 없다. 조용히 보정하지 말고
입력을 거부하거나 별도 convention ID를 요구해야 한다.

1. **윤달 출생**: 윤달을 같은 번호의 평달로 볼지, 대상 연도의 윤달을 찾을지에 대한
   정본 규칙을 확보하지 못했다.
2. **생일 30일인데 대상 음력월이 29일인 경우**: 29일로 절단할지 다음 달 1일로
   넘길지 확인되지 않았다.
3. **세는나이의 기준일**: 현대 예는 “그 해 31세”를 사용하지만 음력 설 전후를
   따로 나누는지 원전에서 확인하지 못했다. V1은 `targetYear - birthYear + 1`을
   명시적 convention으로 쓰거나 계산된 나이를 직접 받는다.
4. **연도 경계**: 토정비결 대상 연도를 음력 정월, 입춘, 양력 1월 1일 중 어디서
   넘기는지 단일 원전 계약을 확보하지 못했다. API는 `targetYear`를 명시적으로
   받고 자동으로 “올해”를 판단하지 않는다.
5. **144 점사 정본**: 춘호재 스캔, 장서각본, 인쇄본과 후대 해설 사이에 이문과
   착간이 있다. KCI 연구도 빠른 판본 변화를 지적한다.

### 2.6 괘표·해석문 배포 결정

춘호재 스캔의 앞 24개 면에는 여섯 코드씩 `111`부터 `863`까지 144개 코드가 배열되어
있어 독립 전사본의 기준 이미지로 쓸 수 있다. 그러나 자동 OCR 텍스트 층이 없고
원본 손상이 있으므로 다음 절차 없이는 shipping하지 않는다.

1. `tojeong-chunhojae-144@1.0.0`처럼 소장본을 pack ID에 포함한다.
2. 서로 독립적인 두 번의 수기 전사 후 문자 단위 diff를 해소한다.
3. 각 항목에 scan page와 영역 좌표를 provenance로 남긴다.
4. 알 수 없는 글자를 임의 보충하지 않고 `缺字`로 보존한다.
5. 한문 원문, 자체 한국어 직역, 현대 상담용 서술을 세 파일로 분리한다.
6. 현대 한국어 번역·해설을 베끼지 않고 새로 작성한다.

권리상 주의:

- Commons 항목은 해당 파일을 한국의 퍼블릭 도메인 및 기계적 PD 스캔으로
  표시하지만, 동시에 미국 퍼블릭도메인 태그가 더 필요하다는 경고를 표시한다.
  전 세계 npm/GitHub 배포 전에는 이 상태를 별도로 확인해야 한다.
- 장서각 페이지 하단은 “Some Rights Reserved”라고만 표시한다. 원문 이미지의
  재배포 허락으로 해석하면 안 된다.
- 국립중앙도서관은 저작권이 소멸되었거나 허락된 디지털화 자료를 무료 이용할 수
  있다고 설명하지만, 무료 열람과 Apache-2.0 재배포는 같은 권리가 아니다.
  ([국립중앙도서관 디지털화 자료 안내](https://nl.go.kr/NL/contents/N10200000000.do))

따라서 **계산 엔진과 144 코드까지는 즉시 구현 가능**하고, 전체 고전 점사 corpus는
전사·권리 검토를 별도 release gate로 두는 것이 안전하다.

## 3. 주역 선천·후천 배치

### 3.1 내부 표현

모든 선은 아래에서 위로 저장한다. `1=양(실선)`, `0=음(절선)`이다.

| 괘  | 한자 | 아래→위 bits | Unicode |
| --- | ---- | ------------ | ------- |
| 건  | 乾   | `111`        | ☰      |
| 태  | 兌   | `110`        | ☱      |
| 리  | 離   | `101`        | ☲      |
| 진  | 震   | `100`        | ☳      |
| 손  | 巽   | `011`        | ☴      |
| 감  | 坎   | `010`        | ☵      |
| 간  | 艮   | `001`        | ☶      |
| 곤  | 坤   | `000`        | ☷      |

이 방향을 뒤집으면 진·간, 손·태가 서로 바뀌므로 public type에
`lineOrder: "bottom-to-top"`을 반드시 넣는다.

### 3.2 `shaoyong-xiantian@1.0.0`

《설괘》의 `天地定位, 山澤通氣, 雷風相薄, 水火不相射`는 네 쌍의 대대를
제시한다. 송대 이후 주석 전통은 이를 선천 원도에 배치하고
`乾一兌二離三震四巽五坎六艮七坤八` 순서를 사용한다.
([《설괘》 원문](https://zh.wikisource.org/zh/%E6%98%93%E5%82%B3/%E8%AA%AA%E5%8D%A6),
[선천 주석과 순서](https://ctext.org/wiki.pl?chapter=760403))

전통적으로 남쪽을 도식 위에 놓을 때:

| 방위 | 괘  | 선천수 |
| ---- | --- | -----: |
| 남   | 乾  |      1 |
| 남동 | 兌  |      2 |
| 동   | 離  |      3 |
| 북동 | 震  |      4 |
| 북   | 坤  |      8 |
| 북서 | 艮  |      7 |
| 서   | 坎  |      6 |
| 남서 | 巽  |      5 |

profile 이름에 복희가 아니라 **소옹**을 넣는 이유는, 현 도상을 복희가 실제로
제작했다는 역사적 사실을 원문으로 검증할 수 없기 때문이다.

### 3.3 `shuogua-houtian@1.0.0`

《설괘》는 `帝出乎震 → 齊乎巽 → 相見乎離 → 致役乎坤 → 說言乎兌 →
戰乎乾 → 勞乎坎 → 成言乎艮` 순서를 제시하고, 이어서 진=동, 손=동남,
리=남, 건=서북, 감=북, 간=동북 등의 방위를 풀이한다.
([《설괘》 원문](https://zh.wikisource.org/zh/%E6%98%93%E5%82%B3/%E8%AA%AA%E5%8D%A6))

| 방위 | 괘  |
| ---- | --- |
| 동   | 震  |
| 남동 | 巽  |
| 남   | 離  |
| 남서 | 坤  |
| 서   | 兌  |
| 북서 | 乾  |
| 북   | 坎  |
| 북동 | 艮  |

후천의 낙서수 `坎1·坤2·震3·巽4·中5·乾6·兌7·艮8·離9`는 방위 표와 다른
추가 convention이다. V1 방위 API에 암묵적으로 섞지 않고 별도
`luoshu-number@...` profile을 조사한 뒤 추가한다.

## 4. 주역 괘 생성

### 4.1 공통 효 값

|  값 | 이름 | 본괘 | 변괘 | 동효   |
| --: | ---- | ---- | ---- | ------ |
|   6 | 노음 | 음   | 양   | 예     |
|   7 | 소양 | 양   | 양   | 아니오 |
|   8 | 소음 | 음   | 음   | 아니오 |
|   9 | 노양 | 양   | 음   | 예     |

주희 《주역본의》의 서의는 세 변 뒤 남은 책수를 4로 나누어
`36→9, 32→8, 28→7, 24→6`을 얻고, 노효는 변하며 소효는 그대로라고
설명한다.
([Chinese Text Project의 《周易本義》 서지·스캔 연결](https://ctext.org/wiki.pl?if=gb&res=73027),
[《原本周易本義》의 수와 변효 요약](https://ctext.org/wiki.pl?chapter=815572))

### 4.2 `three-coin-yiyin@1.0.0`

명대 《易隱》의 `以錢代蓍說`은 동전 세 닢을 던져 뒷면 수로 효를 정하고,
아래에서 위로 괘를 만든다고 명시한다.
([《易隱》 원문](https://ctext.org/wiki.pl?chapter=436217))

API에서는 번역에 따라 뒤집히는 `head/tail`을 쓰지 않고
`back`과 `inscribedFace`를 쓴다.

```text
back count 0 (純字) -> 6, 노음, ×
back count 1        -> 7, 소양, 단(—)
back count 2        -> 8, 소음, 절(-- )
back count 3        -> 9, 노양, ○
```

공정하고 독립적인 동전이라면 정확한 확률은 다음과 같다.

```text
P(6, 7, 8, 9) = (1, 3, 3, 1) / 8
```

여섯 번의 세 동전 결과를 입력으로 받으면 완전히 결정적이며, 난수 생성은 core 밖에서
한다. RNG를 제공한다면 seed, PRNG 이름·버전과 여섯 번의 실제 면을 결과에 남긴다.

### 4.3 `zhuxi-yarrow@1.0.0`

《계사전》은 50 가운데 49를 쓰고, 둘로 나누고 하나를 걸고, 넷씩 세고, 나머지를
끼우는 과정을 세 번 되풀이하는 뼈대를 기록한다.
([《계사전》 상](https://ctext.org/book-of-changes/xi-ci-shang))
주희의 《주역본의·서의》가 이를 재현 가능한 세부 절차로 풀어 쓴다.

한 효의 결정적 trace:

1. 매 효마다 49개로 시작한다.
2. 좌우 두 **비어 있지 않은** 더미 `L, R`로 나눈다.
3. 오른쪽에서 하나를 빼어 건다.
4. 왼쪽과 오른쪽을 각각 넷씩 덜어내고, 나머지가 0이면 4로 센다.
5. 건 하나와 양쪽 나머지를 제거한다.
6. 남은 책으로 2–5를 두 번 더 반복한다. 한 효에 총 세 변이다.
7. 남은 수는 `36/32/28/24` 가운데 하나이고 4로 나눠 `9/8/7/6`을 얻는다.
8. 다시 49개로 시작하여 아래 효부터 여섯 효를 만든다. 총 18변이다.

재생 가능한 끝값 오라클:

```text
# 노양 9
start 49
change 1: L=1, R=48; hang=1; remainders=1+3; remove=5; remain=44
change 2: L=1, R=43; hang=1; remainders=1+2; remove=4; remain=40
change 3: L=1, R=39; hang=1; remainders=1+2; remove=4; remain=36
line = 36 / 4 = 9

# 노음 6
start 49
change 1: L=4, R=45; hang=1; remainders=4+4; remove=9; remain=40
change 2: L=4, R=36; hang=1; remainders=4+3; remove=8; remain=32
change 3: L=4, R=28; hang=1; remainders=4+3; remove=8; remain=24
line = 24 / 4 = 6
```

물리적으로 사람이 “임의로” 더미를 나누는 행위의 확률분포는 원문이 수학적으로
정의하지 않는다. 흔히 인용하는 시초 확률 `6:7:8:9 = 1:5:7:3 / 16`을 API 보장으로
쓰려면 분할 방식과 표본공간을 별도 profile로 명시해야 한다. trace 기반 계산 자체와
그 확률 모델을 혼동하지 않는다.

### 4.4 본괘·변괘와 64괘 lookup

```text
baseBit(6|8) = 0
baseBit(7|9) = 1

changedBit(6) = 1
changedBit(9) = 0
changedBit(7|8) = baseBit

lowerTrigram = lines[0..2]
upperTrigram = lines[3..5]
```

패턴→괘서·한문 괘명 표는 통상 주역 순서를 그대로 고정한다. Chinese Text Project의
《易經》 목차는 `乾, 坤, 屯, 蒙 ... 既濟, 未濟` 64괘 순서를 제공한다.
([64괘 목차](https://ctext.org/book-of-changes/yi-jing))

표시 문자는 Unicode 17의 `U+4DC0..U+4DFF`가 같은 괘서 순서다. 즉 괘서가 `n`이면
glyph code point는 `0x4DBF + n`이다.
([Unicode 17 names list](https://www.unicode.org/charts/nameslist/n_4DC0.html))
Unicode data file을 복사해 bundle한다면 OSI 승인 `Unicode-3.0` 고지 의무를 따른다.
([Unicode 라이선스 정책](https://www.unicode.org/policies/licensing_policy.html))

독립 fixture:

```text
[7,7,7,7,7,7] -> #1  乾, moving=[], changed=#1 乾
[8,8,8,8,8,8] -> #2  坤, moving=[], changed=#2 坤
[9,7,7,7,7,7] -> #1  乾, moving=[1], changed=#44 姤
[7,8,7,8,7,8] -> #63 既濟, moving=[], changed=#63 既濟
[8,7,8,7,8,7] -> #64 未濟, moving=[], changed=#64 未濟

six casts of [back,back,back]
  -> [9,9,9,9,9,9] -> #1 乾, all six moving -> #2 坤

six casts of [inscribedFace,inscribedFace,inscribedFace]
  -> [6,6,6,6,6,6] -> #2 坤, all six moving -> #1 乾
```

### 4.5 해석 규칙은 별도 제품

0–6개의 동효 중 어느 괘사·효사를 우선 읽는지는 주희 계통, 화주림 계통과 현대
관행이 같지 않다. 《易隱》의 삼전법도 납갑·육친·세응을 사용하는 더 큰 체계의 일부다.
따라서 V1 core는 다음만 반환한다.

- 본괘·변괘
- 여섯 효의 `6/7/8/9`, 음양과 동정
- 상괘·하괘
- 괘서, 한문 괘명과 선택적 고전 원문 ID
- 생성 profile과 재생 trace

길흉 판정, 질문 분야별 의미, 여러 동효의 독법은 출전별 Tradition Pack으로 둔다.

## 7. 검증하지 못한 주장

- 이지함이 현전 144항 판본을 직접 저술했다는 주장
- 현전 토정비결에 모든 판본을 대표하는 단 하나의 정본 괘표가 있다는 주장
- 선천도가 역사적 복희의 실제 도상이고 후천도가 문왕의 실제 도상이라는 주장
- 토정비결 144코드나 주역 괘가 현실 사건의 확률을 예측한다는 주장
- 물리적 시초 분할이 아무 가정 없이 정확히 `1:5:7:3` 확률을 만든다는 주장
- 여러 동효가 나왔을 때 하나만이 정답인 보편적 독법이 있다는 주장

이 항목들은 제품 문구에서도 사실처럼 광고하지 않는다.
