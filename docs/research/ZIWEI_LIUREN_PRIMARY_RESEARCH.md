# 자미두수·육임정단 1차 원전 조사

> 목적: 오마이사주가 특정 현대 라이브러리의 구현을 복제하지 않고도, 공개 고전 규칙을 근거로 재현 가능한 계산 코어를 설계할 수 있는지 확인한다.
> 범위: 자미두수의 명반 골격과 14주성, 대육임의 천지반·사과·삼전. 해석 문구, 길흉 점수, 유료 서비스의 결과 복제는 범위 밖이다.

## 결론

- 두 기능 모두 **출처와 학파 선택을 버전 프로필로 고정하면** 결정론적 코어로 구현할 수 있다.
- 자미두수의 최소 완결 범위는 `명궁·신궁 → 12궁 → 오행국 → 자미/천부 위치 → 14주성`이다. 이 부분은 《紫微斗數全書》 권2에 규칙과 일자표가 함께 있어 독립 회귀 오라클을 만들 수 있다.
- 육임의 최소 완결 범위는 `월장 → 천지반 → 사과 → 구종법(九宗法) → 삼전`이다. 《六壬指南》과 사고전서본 《六壬大全》 권1이 같은 골격을 제시한다.
- 다만 두 체계 모두 단일한 “절대 정답”은 없다. 윤월, 입춘/설 경계, 야자시, 섭해 계산, 별책·복음·반음의 세부 우선순위가 학파별로 갈린다. API 응답에 `profileId`와 선택 규칙을 반드시 남겨야 한다.
- `laravel-fortune`의 육임 구현은 월장을 음력 월 숫자로 바로 찾고 720국 설정 파일을 조회한다. 고전의 **중기(中氣) 순간 전환**과 절기 경계에서 달라질 수 있으므로 오마이사주의 기준 구현으로 삼으면 안 된다.
- 아래 고전은 공공영역이지만, Wikisource/Chinese Text Project의 현대 전사문과 현대 오픈소스 코드는 별도 저작권 대상이다. 규칙만 독자적으로 코드화하고 전사문·현대 코드는 복사하지 않는 것이 가장 깨끗하다.

## 1. 자미두수

### 1.1 권장 최소 프로필

프로필 이름 제안:

```text
ziwei-quanshu-core@1.0.0
```

입력은 달력 변환을 다시 수행하지 않고 오마이사주 공통 천문 코어의 확정값을 받는다.

```ts
type ZiweiInput = {
  lunarYearStem: HeavenlyStem;
  lunarMonth: 1 | 2 | ... | 12;
  lunarDay: 1 | 2 | ... | 30;
  isLeapMonth: boolean;
  hourBranch: EarthlyBranch;
  calendarProfileId: string;
  leapMonthPolicy: "whole-leap-as-next-month";
  birthYearBoundary: "lunar-new-year";
  lateZiPolicy: string;
};
```

이 프로필의 산출물은 다음까지만 책임진다.

1. 명궁과 신궁
2. 12궁의 지지·천간·궁명
3. 오행국과 국수
4. 자미·천부 기점
5. 14주성의 궁 위치
6. 계산 프로필과 중간 추적값

보조성, 사화, 묘왕리함, 대한·소한·유년, 해석은 별도 프로필로 확장한다.

### 1.2 공통 인덱스

```text
palaceBranches = [寅, 卯, 辰, 巳, 午, 未, 申, 酉, 戌, 亥, 子, 丑]
hourBranches   = [子, 丑, 寅, 卯, 辰, 巳, 午, 未, 申, 酉, 戌, 亥]
```

`mod`는 음수를 허용하지 않는 수학적 나머지다.

### 1.3 명궁·신궁

《紫微斗數全書》는 정월을 寅에서 시작해 생월까지 순행하고, 그 자리에서 子시를 시작하여 생시까지 **명궁은 역행, 신궁은 순행**한다고 설명한다. 따라서:

```text
m = effectiveLunarMonth - 1
h = hourBranchIndex             // 子=0

mingIndex = mod(m - h, 12)
bodyIndex = mod(m + h, 12)
```

원전 자체 예:

```text
정월 子시 -> 명궁 寅, 신궁 寅
정월 丑시 -> 명궁 丑, 신궁 卯
```

출처: [《紫微斗數全書》 권2의 安命身宮訣](https://zh.wikisource.org/w/index.php?title=%E7%B4%AB%E5%BE%AE%E6%96%97%E6%95%B8%E5%85%A8%E6%9B%B8/%E5%8D%B7%E4%BA%8C&oldid=1963110).

윤월은 같은 대목의 “閏正月作二月推”를 문자 그대로 적용하여 **윤월 전체를 다음 달로 간주**한다.

```text
effectiveLunarMonth = isLeapMonth ? lunarMonth + 1 : lunarMonth
```

12를 넘으면 12궁 계산에서 순환시킨다. 이는 뒤 15일만 다음 달로 넘기는 현대 방식과 다르므로 프로필 이름에 고정한다.

### 1.4 12궁

명궁에서 지지 순행 방향으로 놓을 궁명:

```text
[命, 父母, 福德, 田宅, 官祿, 奴僕, 遷移, 疾厄, 財帛, 子女, 夫妻, 兄弟]
```

이는 원전의 명궁에서 역행하는

```text
[命, 兄弟, 妻妾, 子女, 財帛, 疾厄, 遷移, 奴僕, 官祿, 田宅, 福德, 父母]
```

와 같은 배치다. 현대 API에서는 `妻妾`을 중립적인 `夫妻`, `奴僕`을 표시층에서 `交友`로 번역할 수 있으나, 내부 규칙 키는 원문과 분리한다.

### 1.7 자미·천부와 14주성

국수를 `N`, 음력 일을 `d`라 한다.

```text
a = min { x >= 0 | (d + x) mod N = 0 }
q = (d + a) / N

ziweiIndex = mod(q - 1 + (a가 짝수 ? a : -a), 12)
tianfuIndex = mod(12 - ziweiIndex, 12)
```

첫 식은 원전의 1~30일 오국별 자미 위치표를 수식으로 정규화한 것이다. 반드시 그 표 전체와 대조하여 동치성을 테스트한다. 현대 구현의 독립 교차검증은 [`iztro`의 자미 위치 계산](https://github.com/SylarLong/iztro/blob/9d39f1743bf31c2b3c635c9b9556215d9c90ee2c/src/star/location.ts#L16-L96)에서 확인할 수 있다.

필수 생성 테스트:

- 5개 국 × 음력일 1~30 = 150건을 원전 일자표와 전수 대조
- 모든 12개월 × 12시진 = 144건에서 명·신궁 수식과 단계식 대조
- 14주성이 항상 정확히 14개이며 각 위치가 12궁 안에 있는지 확인
- 자미와 천부가 寅·申에서만 같은 궁이 되는지 확인
- 윤월 정책 경계, 설 전후, 子시 경계를 별도 테스트

### 2.2 월장과 천지반

《六壬指南》의 중기 이후 월장:

| 중기 도달 직후 | 월장 |
| -------------- | ---- |
| 雨水           | 亥   |
| 春分           | 戌   |
| 穀雨           | 酉   |
| 小滿           | 申   |
| 夏至           | 未   |
| 大暑           | 午   |
| 處暑           | 巳   |
| 秋分           | 辰   |
| 霜降           | 卯   |
| 小雪           | 寅   |
| 冬至           | 丑   |
| 大寒           | 子   |

월장은 달력 날짜 0시가 아니라 **해당 중기의 정확한 천문 순간**에 바꾼다. 출처: [《六壬指南》 月將章](https://zh.wikisource.org/zh-hant/%E5%85%AD%E5%A3%AC%E6%8C%87%E5%8D%97/1).

지반은 `[子,丑,寅,卯,辰,巳,午,未,申,酉,戌,亥]` 고정이다. 월장을 점시의 시지 위에 놓고 순행한다.

```text
branchIndex: 子=0 ... 亥=11
H(e) = branch(mod(e + monthGeneralIndex - hourBranchIndex, 12))
```

`H(e)`는 지반 `e` 위의 천반 지지다. 역함수 `E(t)`는 천반 `t` 아래의 지반 지지다.

원전 직접 오라클:

```text
雨水 이후, 월장 亥, 午시
午 지반 위 = 亥
未 지반 위 = 子
```

출처: [《六壬大全》 권1 十干寄宮](https://zh.wikisource.org/w/index.php?title=%E5%85%AD%E5%A3%AC%E5%A4%A7%E5%85%A8/1&oldid=854569).

사과는 중복을 없애지 않고 다음 순서로 만든다.

```text
L1 = { lower: dayStem,   upper: H(lodge(dayStem)) }
L2 = { lower: L1.upper,  upper: H(L1.upper) }
L3 = { lower: dayBranch, upper: H(dayBranch) }
L4 = { lower: L3.upper,  upper: H(L3.upper) }
```

첫 과의 아래만 천간이고 나머지는 지지다. 오행 관계는 다음 표로 판정한다.

### 2.4 삼전 선택: 구종법

구종법의 우선순위와 예외는 [《六壬大全》 권1 起例](https://zh.wikisource.org/w/index.php?title=%E5%85%AD%E5%A3%AC%E5%A4%A7%E5%85%A8/1&oldid=854569) 및 [《六壬指南》](https://zh.wikisource.org/zh-hant/%E5%85%AD%E5%A3%AC%E6%8C%87%E5%8D%97/1)을 기준으로 한다.

#### A. 일반적인 초전 선택

1. **賊克**: 아래가 위를 극하는 과(`lower controls upper`)의 상신을 우선 후보로 한다. 하나도 없을 때만 위가 아래를 극하는 과의 상신을 후보로 한다.
2. 후보가 하나면 그것이 초전이다.
3. **比用**: 후보가 여러 개면 일간과 음양이 같은 상신만 남긴다. 하나가 되면 초전이다. 전부 같거나 전부 다르면 섭해로 간다.
4. **涉害**: 각 후보 상신이 현재 올라탄 지반 자리에서 자기 본궁까지 지지 순행한다. 시작점은 제외하고 본궁은 포함한다.
   - `下賊上` 후보면 경로의 지지 및 그 지지에 기숙한 천간 중 **후보 상신을 극하는** 오행 노드 수를 센다.
   - `上克下` 후보면 경로 노드 중 **후보 상신이 극하는** 오행 노드 수를 센다.
   - 가장 깊은 수를 선택한다.
   - 동수면 후보가 올라탄 지반을 `孟(寅申巳亥) > 仲(子午卯酉) > 季(辰戌丑未)` 순으로 우선한다.
   - 그래도 동수면 이 프로필은 원문의 “柔辰剛日”을 `양일은 일간측 과, 음일은 일지측 과`로 정규화한다. 이 마지막 정규화는 버전 결정이며 전수 테스트의 대상이다.
5. **遙克**: 직접 극이 하나도 없으면 사과의 상신 중 일간을 극하는 상신을 먼저 찾고, 없으면 일간이 극하는 상신을 찾는다. 복수면 比用 규칙을 적용한다.
6. 일반법에서 초전이 정해지면 `중전 = H(초전)`, `말전 = H(중전)`이다.

섭해의 계산 오라클은 《六壬大全》 권7의 `正月 丁卯日 丑時 亥將` 예다. `丑 위의 亥`는 본궁까지 가며 辰·戊·未·己·戌의 토극수를 만나 5중, 다른 후보는 1중이므로 초전은 亥다. 천반 연쇄를 적용하면 이 프로필의 삼전은 `亥·酉·未`가 된다. [Chinese Text Project 전사](https://ctext.org/wiki.pl?chapter=350312&if=en).

#### B. 무극·무요극과 특수과

특수반은 먼저 식별하고, 원전의 전용 규칙을 적용한다.

- **伏吟**: 월장과 시지가 같아 천반과 지반이 일치한다.
  - 극이 있으면 해당 극을 초전으로 쓴다.
  - 무극이면 양일은 일간 상신, 음일은 일지를 초전으로 삼는다.
  - 중·말전은 형(刑)을 차례로 취한다.
  - 초전이 자형이면 양일은 일지, 음일은 일간 상신으로 중전을 바꾸고, 다시 자형이면 충을 말전으로 한다.
- **返吟**: 월장과 시지가 충이라 천지반이 서로 반대다.
  - 극이 있으면 일반 賊克 계열을 쓴다.
  - 무극인 `丁未·己未·辛未·丁丑·己丑·辛丑` 여섯 날은 井欄으로 처리한다. 초전은 일지의 역마, 중전은 일지 상신, 말전은 일간 상신이다.
- 직접극과 요극이 없고 사과의 고유 쌍이 네 개면 **昴星**:
  - 양일: 초전 `H(酉)`, 중전 일지 상신, 말전 일간 상신
  - 음일: 초전 `E(酉)`, 중전 일간 상신, 말전 일지 상신
- 고유 과가 세 개면 **別責**:
  - 양일 초전: 일간의 오합 상대 천간 기궁 위의 상신
  - 음일 초전: 일지 삼합에서 앞선 지지 위의 상신
  - 중·말전은 모두 일간 상신
- 고유 과가 두 개이고 팔전 조건이면 **八專**:
  - 양일 초전: 일간 상신에서 자신을 1로 세어 순행 세 번째 지지
  - 음일 초전: 일지 상신에서 자신을 1로 세어 역행 세 번째 지지
  - 중·말전은 모두 일간 상신

`別責`의 “삼합에서 앞선 지지” 순서와 복음 자형 분기는 전통 용어를 코드 규칙으로 옮기는 과정에서 오프바이원 위험이 크다. 각 분기별 고전 실례를 하나 이상 확보하기 전에는 프로덕션 완료로 표시하지 않는다.

원문이 “해당 천반”을 표로 제시하는 예는 날짜만 재구성해 테스트하지 말고, 표에 적힌 월장·시각·사과를 fixture에 함께 보존해야 한다.

필수 전수·경계 테스트:

- `60일주 × 12월장 × 12시지 = 8,640` 입력을 전수 실행
- 삼전이 항상 세 지지로 끝나고 무한 루프나 미분류 입력이 없는지 확인
- 구종법 9개 경로가 각각 최소 한 번 이상 실행되는지 확인
- 같은 `월장-시지` 상대차는 같은 천반 이동량을 갖는지 확인
- 12개 중기 각각 `-1ms / 정확한 순간 / +1ms`에서 월장 전환 확인
- 섭해 fixture에는 후보별 경로, 지지 극수, 기궁 천간 극수를 snapshot으로 저장
- 고전 오라클과 별개로 MIT 엔진 두 개와 차등 테스트하되, 둘이 일치한다는 이유만으로 정답 처리하지 않음

### 2.7 `laravel-fortune`과의 차이

고정 commit의 [`YukimService`](https://github.com/wangta69/laravel-fortune/blob/3b97333d8aa2a25bf347ac818a424a5a5df7a6c0/src/Services/YukimService.php#L17-L18)는 음력 1~12월을 월장 亥~子에 직접 대응시키고, [천반 구성부](https://github.com/wangta69/laravel-fortune/blob/3b97333d8aa2a25bf347ac818a424a5a5df7a6c0/src/Services/YukimService.php#L242-L286)는 그 값을 사용한다. 삼전은 계산 추적을 만들기보다 [미리 계산된 720국 설정 조회](https://github.com/wangta69/laravel-fortune/blob/3b97333d8aa2a25bf347ac818a424a5a5df7a6c0/src/Services/YukimService.php#L133-L148)에 의존한다.

따라서 오마이사주 구현은:

1. 음력 월이 아니라 기존 절기 엔진의 정확한 중기를 사용하고,
2. 720국 정답 파일을 베끼지 않으며,
3. 사과·후보·섭해 극수·선택 경로를 계산 결과에 노출하고,
4. 720개 상대국 또는 8,640개 전체 입력을 생성 테스트로 검증한다.

이렇게 해야 절기 경계 오류를 피하고 “왜 이 삼전인가”를 설명할 수 있다.

1. 구현자는 고전에서 정리한 이 문서의 규칙과 자체 테스트 벡터만 본다.

3. 차등 테스트 도구는 테스트 전용 의존성 또는 외부 실행기로 격리한다.
4. 불일치가 나면 다수결이 아니라 원문 규칙·판본·프로필 차이로 분류한다.
5. 모든 공개 API에 `calculationProfile`, `calendarProfile`, `sourceEdition`을 포함한다.
6. 해석 문구는 고전/현대 문구를 복사하지 않고 오마이사주 고유 문장으로 작성한다.

## 4. 구현 완료의 정의

### 자미두수 최소 완료

- 명·신궁, 12궁, 궁간, 오행국, 자미·천부, 14주성이 순수 함수로 계산됨
- 원전 150칸 자미 일자표 전수 일치
- 윤월·설·子시 정책이 API와 테스트명에 노출됨
- 현대 엔진 없이도 기대값을 재생성할 수 있음

### 육임 최소 완료

- 중기 순간으로 월장을 정하고 천지반·사과를 계산함
- 구종법 9경로가 모두 계산 추적과 함께 종료됨
- 8,640개 전수 입력이 미분류 없이 삼전을 냄
- 원전의 천반, 섭해 극수, 삼전 실례가 모두 일치함
- 특히 別責 삼합 방향, 伏吟 자형, 返吟 井欄에 판본별 fixture가 확보됨

### “laravel-fortune 전체 범위”에 가까워지려면

이 문서의 두 코어 외에도 천장·귀인·신살·과체 분류·단과 해석, 자미두수의 전 별군과 운한을 추가해야 한다. 택일, 토정비결, 주역, 육효, 자미두수, 육임은 서로 입력과 검증법이 다른 별도 수직 모듈이다. 하나의 거대한 `fortune()` 함수나 공유 길흉 점수로 합치지 말고, 각각 출처·학파·버전을 가진 엔진으로 만들고 상위 계층에서 설명만 조합하는 것이 안전하다.
