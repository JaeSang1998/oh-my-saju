# 신살·택일 1차 원전 조사와 오마이사주 구현안

조사일: 2026-07-30
범위: 신살, 혼례 택일, 입택·이사 택일, 방향·가족 입력, 일일 추천 점수
결론의 성격: 전통 규칙을 기술한 역사 자료의 재현안이지, 인과효과나 미래 예측의 과학적 검증이 아니다.

## 결론

오마이사주에는 다음 세 팩을 서로 독립적으로 넣는 것이 가장 안전하다.

1. `sanming-shensha-curated@1.0.0`
   - 《三命通會》에서 산식이 명확하고 스스로 핵심이라고 한 신살만 계산한다.
   - 결과는 `match / no-match / partial / disputed`인 원문 규칙 판정이다.
   - 신살 하나로 길흉·직업·질병·수명·혼인 결과를 단정하지 않는다.
2. `nam-byeong-gil-electional@1.0.0`
   - 조선의 남병길이 1867년에 편찬한 《選擇紀要》와 그 바탕인 《欽定協紀辨方書》의 혼례·입택 규칙 중 산식이 확인되는 항목만 사실로 계산한다.
   - 저자가 직접 허위·억설로 배제한 합혼 구궁, 길월의 “妨夫·妨妻”, 주당(周堂), 근거 없는 잡살은 기본 프로필에서 제외한다.
3. `oh-my-saju-election-ranking@1.0.0`
   - 여러 후보일을 정렬하는 숫자는 고전 점수가 아니라 오마이사주의 공개된 제품 정책으로만 제공한다.
   - 출력 필드도 `luckProbability`가 아니라 `rankingScore`로 한다.

즉, “고전에서 이 사실을 어떻게 계산했는가”와 “서비스가 일정 후보를 어떤 순서로 보여주는가”를 데이터 구조, 버전, 문구 모두에서 분리해야 한다.

## 2. `sanming-shensha-curated@1.0.0`

### 2.1 기본 앵커

《三命通會》의 표기는 “寅午戌生人”처럼 생년 지지를 주체로 삼는다. 따라서 소스 충실 기본값은 다음과 같다.

- `anchor = natal.year.branch`
- `targets = natal.year/month/day/hour.branch`
- 같은 신살이 여러 기둥에 있으면 위치별 match를 모두 반환
- 시각 미상은 연·월·일까지만 검사하고 `partial`을 반환

현대 실무에서 흔한 “연지와 일지를 둘 다 앵커로 검사”는 별도 학파 프로필로 만들 수 있지만, 이 자료만으로는 같은 원전 규칙이라고 주장할 수 없다. `year-and-day-anchor`를 추가하려면 별도의 원전 ID와 버전을 붙인다.

### 2.2 삼합에서 바로 계산되는 8종

《三命通會》는 장성을 삼합의 가운데(旺), 화개를 삼합의 묘고(庫), 함지·도화를 목욕 자리로 설명한다. 역마·겁살·망신·재살·육액도 같은 네 삼합군에서 계산한다. 특히 함지는 단순 지지표 외에 천간·납음 자격을 더 요구한다는 문장이 있으므로, v1은 지지 패턴과 자격 여부를 분리한다. 근거는 [장성·화개·함지](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83_%28%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC%29/%E5%85%A8%E8%A6%BD), [역마](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83/%E5%8D%B7%E4%B8%89), [겁살·망신과 재살·육액](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83_%28%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC%29/%E5%85%A8%E8%A6%BD)이다.

| 연지 삼합군 | 역마 驛馬 | 장성 將星 | 화개 華蓋 | 함지/도화 咸池 | 겁살 劫煞 | 망신 亡神 | 재살 災煞 | 육액 六厄 |
| ----------- | --------: | --------: | --------: | -------------: | --------: | --------: | --------: | --------: |
| 申子辰      |        寅 |        子 |        辰 |             酉 |        巳 |        亥 |        午 |        卯 |
| 寅午戌      |        申 |        午 |        戌 |             卯 |        亥 |        巳 |        子 |        酉 |
| 巳酉丑      |        亥 |        酉 |        丑 |             午 |        寅 |        申 |        卯 |        子 |
| 亥卯未      |        巳 |        卯 |        未 |             子 |        申 |        寅 |        酉 |        午 |

권장 결과 형식:

```json
{
  "ruleId": "sanming.shensha.travel-horse",
  "ruleVersion": "1.0.0",
  "anchor": { "kind": "year-branch", "value": "子" },
  "target": "寅",
  "matches": [{ "position": "month", "value": "寅" }],
  "status": "match",
  "claimLevel": "classical-pattern"
}
```

함지는 아래처럼 두 단계로 낸다.

- `branchPatternMatch`: 위 표의 지지 일치
- `sanmingQualification`: `matched | not-matched | unresolved`

원문의 “天干納音於地同類”를 정확한 데이터 계약으로 확정하기 전에는 `branchPatternMatch`만으로 “도화살 확정”이라고 하지 않는다.

### 2.3 고진·과숙

《三命通會》는 계절 3지의 다음 모서리를 고진, 이전 모서리를 과숙으로 잡는다. [원문 산식](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83_%28%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC%29/%E5%85%A8%E8%A6%BD)은 다음 표로 환원된다.

| 연지 군 | 고진 孤辰 | 과숙 寡宿 |
| ------- | --------: | --------: |
| 亥子丑  |        寅 |        戌 |
| 寅卯辰  |        巳 |        丑 |
| 巳午未  |        申 |        辰 |
| 申酉戌  |        亥 |        未 |

이름을 현대의 실제 독신·이혼·가족관계 결과로 번역하지 않는다. 출력 설명은 “원전의 지지 패턴 명칭”까지만 허용한다.

### 2.4 천을귀인

《選擇紀要》의 교정표와 《三命通會》는 다음 두 지지를 제시한다. [표와 음·양귀인 분할](https://zh.wikisource.org/zh-hant/%E9%81%B8%E6%93%87%E7%B4%80%E8%A6%81/%E4%B8%8A%E7%B7%A8), [여러 분할설을 함께 기록한 《三命通會》](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83/%E5%8D%B7%E4%B8%89)을 근거로 한다.

| 기준 천간 | 후보 지지 |
| --------- | --------- |
| 甲·戊·庚  | 丑, 未    |
| 乙·己     | 子, 申    |
| 丙·丁     | 酉, 亥    |
| 辛        | 寅, 午    |
| 壬·癸     | 卯, 巳    |

기본 프로필은 `unsplit-pair`로 두 지지를 모두 검사한다. 다음 분할설은 같은 값으로 섞지 않는다.

- 동지 이후 양귀·하지 이후 음귀
- 낮·밤 분할
- 寅·申을 기준으로 한 분할
- 일출·일몰을 기준으로 한 분할

원전도 낮·밤의 경계를 子/午로 볼지 실제 일출·일몰로 볼지 등의 설을 “臆說”이라 비판한다. 분할 프로필을 제공하려면 위치, 날짜, 일출·일몰 계산까지 입력 계약에 넣어야 한다.

### 2.5 건록·문창

`祿` 표는 [《三命通會》 권3](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83/%E5%8D%B7%E4%B8%89)과 [《選擇紀要》](https://zh.wikisource.org/zh-hant/%E9%81%B8%E6%93%87%E7%B4%80%E8%A6%81/%E4%B8%8A%E7%B7%A8)에 일치한다. 문창은 《選擇紀要》가 녹의 앞 네 자리라고 명시한다.

| 일간 |  甲 |  乙 |  丙 |  丁 |  戊 |  己 |  庚 |  辛 |  壬 |  癸 |
| ---- | --: | --: | --: | --: | --: | --: | --: | --: | --: | --: |
| 건록 |  寅 |  卯 |  巳 |  午 |  巳 |  午 |  申 |  酉 |  亥 |  子 |
| 문창 |  巳 |  午 |  申 |  酉 |  申 |  酉 |  亥 |  子 |  寅 |  卯 |

일간을 앵커로 하고 네 지지 위치를 검사한다. “시험 합격” 같은 사건 예측은 하지 않는다.

### 2.6 공망

《三命通會》는 열 천간이 닿지 않는 두 지지를 순공망으로 설명하면서, 공망이 있으면 무조건 흉하다고 할 수 없다고 반복해서 경계한다. [공망 산식과 예외](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83_%28%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC%29/%E5%85%A8%E8%A6%BD)를 다음 표로 구현할 수 있다.

| 순     | 공망 |
| ------ | ---- |
| 甲子旬 | 戌亥 |
| 甲戌旬 | 申酉 |
| 甲申旬 | 午未 |
| 甲午旬 | 辰巳 |
| 甲辰旬 | 寅卯 |
| 甲寅旬 | 子丑 |

API는 `dayPillarVoidBranches`와 각 위치의 일치만 반환한다. “무효화”처럼 다른 모든 규칙을 자동 취소하는 로직은 넣지 않는다.

### 2.7 양인/양날의 학파 충돌

원전 한 대목은 “녹의 앞 한 자리”로 음간까지 계산하고, 뒤에서는 자평가가 오직 다섯 양간에만 날이 있다고 했다고 기록한다. [같은 권 안의 충돌](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83_%28%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC%29/%E5%85%A8%E8%A6%BD)을 숨기지 않는다.

프로필을 둘로 분리한다.

- `blade-after-lu-all-stems`
  - 甲卯, 乙辰, 丙午, 丁未, 戊午, 己未, 庚酉, 辛戌, 壬子, 癸丑
- `yang-stems-only`
  - 甲卯, 丙午, 戊午, 庚酉, 壬子

기본값을 어느 쪽으로 할지는 해석 팩이 결정해야 하며, 엔진은 프로필 ID 없이 임의로 하나를 고르지 않는다.

### 2.8 v1에서 제외할 신살

《三命通會》 자체가 신살이 120여 종으로 늘어나 천착·지리멸렬해졌다고 비판하고 핵심만 남긴다. [총론](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83_%28%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC%29/%E5%85%A8%E8%A6%BD)의 태도를 v1 큐레이션 기준으로 삼는다.

다음은 기본 팩에서 제외한다.

- 성별·성적 순결·배우자 사망을 단정하는 홍염, 고란과숙 등의 후대식 문구
- 자살·익사·형벌·요절 같은 사건명을 바로 예측하는 잡살
- 원전 산식보다 현대 블로그 표만 확인되는 신살
- 같은 이름인데 기준이 연지·일지·월지로 갈리고 출처를 식별할 수 없는 표
- 신살의 개수를 단순 합산한 “신살 총점”

## 3. 택일에서 먼저 고정해야 할 달력 계약

### 3.1 절월

《欽定協紀辨方書》의 월표는 “清明三月節”, “立秋七月節”, “立冬十月節”, “大雪十一月節”처럼 절입에서 월건이 바뀐다고 명시한다. 예를 들어 [3월표](https://zh.wikisource.org/zh/%E6%AC%BD%E5%AE%9A%E5%8D%94%E7%B4%80%E8%BE%A8%E6%96%B9%E6%9B%B8_%28%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC%29/%E5%8D%B722)는 청명부터 辰월, [11월표](https://zh.wikisource.org/zh-hans/%E6%AC%BD%E5%AE%9A%E5%8D%94%E7%B4%80%E8%BE%A8%E6%96%B9%E6%9B%B8_%28%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC%29/%E5%8D%B730)는 대설부터 子월로 둔다.

따라서 택일의 `selectionMonth`는 음력 월 번호가 아니라 해당 위치·시간대에서 절입 순간으로 나눈 절월이다.

| 절월 | 시작 절기 | 월지 |
| ---: | --------- | ---: |
|    1 | 입춘      |   寅 |
|    2 | 경칩      |   卯 |
|    3 | 청명      |   辰 |
|    4 | 입하      |   巳 |
|    5 | 망종      |   午 |
|    6 | 소서      |   未 |
|    7 | 입추      |   申 |
|    8 | 백로      |   酉 |
|    9 | 한로      |   戌 |
|   10 | 입동      |   亥 |
|   11 | 대설      |   子 |
|   12 | 소한      |   丑 |

경계 테스트는 각 절입의 `-1 ms / 정확한 순간 / +1 ms` 세 점을 가져야 한다. KASI 특일 API의 날짜만으로 시각 경계를 검증했다고 주장하면 안 된다.

### 3.2 12건제

《選擇紀要》는 월지에서 같은 일지를 建으로 시작해 지지 순서대로 除·滿·平·定·執·破·危·成·收·開·閉를 배치한다. [정확한 표](https://zh.wikisource.org/zh-hant/%E9%81%B8%E6%93%87%E7%B4%80%E8%A6%81/%E4%B8%8A%E7%B7%A8)는 다음 식으로 줄일 수 있다.

```text
officerIndex = mod(dayBranchIndex - selectionMonthBranchIndex, 12)
officers = [建, 除, 滿, 平, 定, 執, 破, 危, 成, 收, 開, 閉]
```

이 값은 고전 사실이다. 어떤 행사에서 각 건제를 얼마만큼 가중할지는 제품 정책이다.

### 3.3 황·흑도 시

《選擇紀要》는 12신을 다음 순서로 두고, 월로 일을 보며 일로 시간을 보는 같은 알고리즘을 적는다.

```text
[青龍(+), 明堂(+), 天刑(-), 朱雀(-), 金櫃(+), 天德(+),
 白虎(-), 玉堂(+), 天牢(-), 玄武(-), 司命(+), 勾陳(-)]
```

青龍의 시작 지지는 다음과 같다.

| 기준 지지 | 青龍 시작 |
| --------- | --------: |
| 寅·申     |        子 |
| 卯·酉     |        寅 |
| 辰·戌     |        辰 |
| 巳·亥     |        午 |
| 子·午     |        申 |
| 丑·未     |        戌 |

근거는 [황·흑도 정국](https://zh.wikisource.org/zh-hant/%E9%81%B8%E6%93%87%E7%B4%80%E8%A6%81/%E4%B8%8A%E7%B7%A8)이다. “황도 시간이 실제 성공률을 높인다”가 아니라 원전상 분류만 출력한다.

## 4. 혼례 택일

### 4.1 원전이 명시한 후보 사실

《選擇紀要》의 육례 항목은 [혼례에 권한 항목과 피한 항목](https://zh.wikisource.org/zh-hant/%E9%81%B8%E6%93%87%E7%B4%80%E8%A6%81/%E4%B8%8A%E7%B7%A8)을 한 줄씩 열거한다.

원전상 `宜`:

- 육덕: 세덕, 세덕합, 천덕, 천덕합, 월덕, 월덕합
- 월은
- 천원
- 모창
- 음양불장
- 오합
- 황도일

원전상 `忌`:

- 본명일과 대충
- 화해·절명
- 월파·월기·월염·염대
- 亥일, 亢일, 그믐
- 피마, 建·閉·平·收, 형·해, 월삼살
- 당시 민속에서 피한 홍사·수사 등

그러나 같은 책은 바로 뒤에서 다음을 분명히 반박한다.

- 합혼 구궁은 외국의 혼인 청을 거절하려 만든 허위 설이라며 삭제한다.
- 여자 생년으로 “배우자·본인·부모에게 해로운 달”을 정하는 길월설은 경전·예서·녹명법에도 근거가 없다며 쓰지 말라고 한다.
- 주당도 가족 위치에서 길흉이 생긴다는 것이 이치에 맞지 않는다고 비판한다.
- 홍사 외 다수 혼례 잡살은 근거 없이 금기만 늘린다고 비판한다.

따라서 기본 프로필은 아래처럼 좁힌다.

### 4.2 v1 구현 범위

구현:

- 절월과 후보일 간지
- 12건제
- 육덕 중 산식이 검증된 값
- 월은·천원·모창 표
- 음양불장 표는 영인본 대조를 통과한 셀만
- 황·흑도 분류
- 두 당사자 각각과 후보일의 명시적 지지 합·충·형·해
- 원전이 제공한 사실 ID와 근거

기본 제외:

- 여자에게만 적용하는 혼인 길월표
- “妨夫·妨妻·妨父母” 판정
- 합혼 구궁
- 주당
- 배우자 사망·불임·이혼 예측
- 28수의 기준 epoch가 고정되지 않은 상태에서의 亢일
- 산식이 확인되지 않은 월기·왕망·천화 등
- 《選擇紀要》 전사본에서 천간 자리에 `巳`가 들어가는 등 이상이 있는 음양불장 셀

음양불장은 구현 전에 영인본과 최소 두 판본을 대조해야 한다. 현재 Wikisource 전사에는 11월 천간 열에 지지 `巳`가 들어가고 12월 지지 열도 한 자가 비정상적으로 보인다. 이 셀을 추측해서 고치면 회귀 오라클이 아니라 새 학설을 만드는 셈이다.

### 4.3 가족 입력

혼례 기본 주체는 결혼 당사자 두 사람뿐이다. 부모·가족의 생년을 넣어 가족에게 해로운 날을 계산하는 것은 이 원전이 오히려 비판한 영역이다.

- `participants`: 두 사람을 성별과 무관하게 대칭 취급
- 각 사람의 충·형·해 결과를 개별 표시
- 한 사람의 불리 판정을 다른 사람의 유리 점수로 상쇄하지 않음
- 부모·가족 입력은 일정 가용성 같은 현실 제약에만 사용

### 4.4 원전 예제

《選擇紀要》는 다음 두 예를 싣는다.

1. 丁卯년, 乙卯 남·丁巳 여, 5월 22일 甲戌을 음양불장·천덕 및 제흉 비해로 선택
2. 壬子 남·己酉 여, 7월 21일 壬申을 제덕 동취·음양불장으로 선택

이 예들은 “상징 간지 fixture”로 보존한다. 그레고리력 날짜로 역산하려면 사용한 역법, 지역 시각, 윤달 여부가 먼저 확정되어야 한다. 또한 일부 플래그가 현재 전사 표와 바로 맞지 않으면 구현을 예제에 억지로 맞추지 말고 `source-transcription-conflict`로 실패시킨다.

## 5. 입택·이사 택일

### 5.1 원전 범위

《選擇紀要》의 [入宅(搬移·歸火)](https://zh.wikisource.org/zh-hant/%E9%81%B8%E6%93%87%E7%B4%80%E8%A6%81/%E4%B8%8A%E7%B7%A8)은 다음을 적는다.

원전상 `宜`:

- 육덕
- 월은
- 천원
- 모창
- 황도일

원전상 `忌`:

- 택장의 본명일, 대충, 화해, 절명
- 월파, 월기, 천화, 왕망, 월염, 수사
- 閉일

하지만 같은 책 하편은 “본명일을 피해야 한다는 명확한 설명은 여러 역서에 없고 특정 도장 경전에만 보인다”고 지적한다. 따라서 `본명일`은 기본 하드 필터가 아니라 `disputed` 사실이다.

### 5.2 이사와 건축·수리의 분리

고전의 방위 규칙 상당수는 단순한 주소 이전이 아니라 다음 행위에 관한 것이다.

- 새집을 짓는 개산·입향
- 기존 집의 어느 방향을 수리하는 수방
- 토목·파토
- 조상 사당·분묘

《欽定協紀辨方書》 권33과 《選擇紀要》 하편은 산·향·방과 주명, 수리 위치를 별도로 논한다. 이를 “서울에서 부산으로 이사하면 남쪽이라 흉” 같은 현대 주소 이전 판정으로 바꾸는 근거는 확인되지 않았다.

따라서 이벤트를 분리한다.

- `move-in`: 입주·이삿짐 반입. 방향 금기를 기본 적용하지 않음.
- `renovation`: 집 내부 수리. 공사 중심점과 수리 구역 방향 필요.
- `groundbreaking`: 착공·토목. 연파·삼살 방향을 역사 규칙 사실로 제공할 수 있음.

### 5.3 가족 구성

원전이 명시하는 주체는 `宅長` 또는 `主命`이다. 모든 가족의 사주를 합산하는 공식은 확인되지 않았다.

오마이사주 v1:

- `principalResident`는 필수
- 다른 거주자는 선택
- 원전 판정은 주거 대표자에 대해 별도 출력
- 다른 거주자의 일지·연지 관계를 보여주는 경우 `product-personalization`으로 표시
- 가족 수가 많다는 이유로 점수가 자동 하락하지 않게 사람별 최저·최고·혼합 상태를 함께 제시

### 5.4 방향을 제공한다면

방향은 먼저 재현 가능한 지리 계산이어야 한다.

1. 출발지와 도착지를 WGS84 위·경도로 받는다.
2. GeographicLib의 inverse geodesic `azi1`로 출발지의 진북 기준 초기 방위각을 구한다.
3. 8방위 또는 24산 경계값을 버전 데이터로 양자화한다.
4. 원점과 목적지가 너무 가까워 방향이 불안정하면 `indeterminate`.
5. 자북, 스마트폰 나침반 방위, 지도 격자북과 혼용하지 않는다.

고전 방위 사실은 `historical-direction@1.0.0`이라는 opt-in 프로필에서만 제공한다.

- 세파: 세지의 정반대 지지
- 삼살: 세지 삼합군의 반대 세 지지
  - 申子辰년 → 巳午未
  - 寅午戌년 → 亥子丑
  - 巳酉丑년 → 寅卯辰
  - 亥卯未년 → 申酉戌

《欽定協紀辨方書》는 세파와 삼살을 특히 무겁게 다루지만, 이는 건축·수리 문맥이다. `move-in` 결과에 자동 이식하지 않는다.

## 6. 사실과 제품 정책을 분리한 점수

### 6.1 3층 결과

```text
astronomy/calendar facts
  └─ classical rule matches (source + version)
       └─ Oh My Saju ranking policy (weights + version)
```

각 후보는 다음을 모두 가진다.

```json
{
  "facts": [],
  "classicalMatches": [],
  "ranking": {
    "policyId": "oh-my-saju-election-ranking",
    "policyVersion": "1.0.0",
    "score": 67,
    "contributions": [],
    "meaning": "후보 정렬용 지표이며 성공률이나 길운 확률이 아님"
  }
}
```

### 6.2 제안 가중치

아래 숫자는 고전의 숫자가 아니라 오마이사주 v1 제품 정책이다.

공통:

| 제품 규칙                       |            가중치 |
| ------------------------------- | ----------------: |
| 기본값                          |                50 |
| 육덕 하나 일치                  | +6, 합계 상한 +18 |
| 월은                            |                +5 |
| 천원                            |                +5 |
| 모창                            |                +4 |
| 황도일                          |                +4 |
| 월파                            |               -16 |
| 후보일과 각 핵심 참여자 연지 충 |      사람마다 -10 |
| 후보일과 각 핵심 참여자 연지 해 |       사람마다 -6 |
| 후보일과 각 핵심 참여자 연지 형 |       사람마다 -4 |
| 필수 달력 사실을 계산할 수 없음 |       점수 `null` |

혼례:

| 제품 규칙       | 가중치 |
| --------------- | -----: |
| 검증된 음양불장 |    +10 |
| 오합            |     +4 |
| 成·開           |     +8 |
| 除·危·定·執     |     +4 |
| 建·閉·破        |    -12 |
| 平·收           |     -6 |

입택:

| 제품 규칙 |                    가중치 |
| --------- | ------------------------: |
| 開·成     |                        +4 |
| 閉        |                       -12 |
| 본명일    | 0, `disputed` 배지만 표시 |

착공·수리 opt-in:

| 제품 규칙               | 가중치 |
| ----------------------- | -----: |
| 작업 방향이 세파와 일치 |    -18 |
| 작업 방향이 삼살과 일치 |    -18 |

최종식:

```text
rankingScore = clamp(0, 100, 50 + sum(contribution))
```

동점은 다음 순서로 정렬한다.

1. 현실 일정 제약을 만족한 후보
2. 고전상 음수 match 수가 적은 후보
3. 점수
4. 날짜 오름차순

점수는 확률도 예언도 아니다. 사용자에게는 반드시 각 `contribution`을 펼쳐서 보여준다.

### 6.3 길흉 문구 제한

허용:

## 7. 독립 회귀 오라클

### 7.1 신살 완전표

각 연지 삼합군마다 12개 후보 지지를 전부 순회해 다음을 검증한다.

- 각 규칙의 target 하나만 match
- 연·월·일·시 위치에 같은 target이 반복되면 모든 위치 반환
- 미상 시주는 앞 세 위치 결과를 보존하고 `partial`

대표 fixture:

```text
anchor year branch 子
驛馬=寅, 將星=子, 華蓋=辰, 咸池=酉,
劫煞=巳, 亡神=亥, 災煞=午, 六厄=卯,
孤辰=寅, 寡宿=戌
```

```text
anchor year branch 寅
驛馬=申, 將星=午, 華蓋=戌, 咸池=卯,
劫煞=亥, 亡神=巳, 災煞=子, 六厄=酉
```

### 7.2 천간 표

- 甲 일간: 건록 寅, 문창 巳, 천을 丑·未
- 辛 일간: 건록 酉, 문창 子, 천을 寅·午
- 양인 두 프로필은 乙辰·丁未·辛戌·癸丑에서 의도적으로 다른 결과

### 7.3 절입 경계

지원 전 연도·전 12절에 대해:

- 경계 `-1 ms`: 이전 절월
- 경계 정확한 순간과 `+1 ms`: 새 절월
- 같은 UTC 순간을 여러 IANA 시간대로 표현해도 천문학적 경계 판정은 동일

### 7.4 12건제 속성

모든 월지 12 × 일지 12 = 144 조합에서:

- 각 월에 12건제가 정확히 한 번씩 출현
- 월지와 같은 일지는 建
- 다음 지지는 除
- 반대 지지는 破

### 7.5 원전 예제

혼례 두 예제는 앞서 적은 상징 fixture로 보존하되, 전사표와 충돌하면 테스트를 억지 통과시키지 않는다. 테스트 상태를 다음처럼 둔다.

```text
pending-source-scan:
  丁卯年 / 乙卯 + 丁巳 / 五月二十二日 甲戌
  丁卯年 / 壬子 + 己酉 / 七月二十一日 壬申
```

입택 항목에는 완전한 그레고리력 worked example이 없으므로 표 속성 테스트와 KASI 달력 교차검증을 오라클로 쓴다.

## 8. 라이선스·출처 처리

### 8.1 고전 원문

- 《三命通會》와 《選擇紀要》 작품 자체는 Wikisource에서 전세계 퍼블릭 도메인으로 표시된다.
- Wikisource의 현대 전사·편집 텍스트는 페이지 하단의 CC BY-SA 조건이 적용된다.
- 따라서 페이지 전체·대형 표를 복사해 코드 데이터로 넣기보다, 퍼블릭 도메인 영인본을 대조하여 규칙을 독립적으로 재입력하고 출전·판본·페이지를 남기는 편이 안전하다.
- 짧은 원문 인용을 문서에 넣을 때는 Wikisource와 편집 이력을 표시한다.

### 8.2 KASI

- 음양력 API와 특일 API는 공공데이터포털에서 `이용허락범위 제한 없음`으로 표시된다.
- API 응답을 회귀 fixture로 저장할 때 제공기관, endpoint, 조회일, 요청 파라미터, 응답 해시를 함께 남긴다.
- API가 주는 절기 “날짜”를 자체 엔진의 절입 “순간” 정본이라고 과장하지 않는다.

### 8.3 타 오픈소스

- laravel-fortune의 공개 기능 목록은 비교 자료일 뿐 계산 권위가 아니다.
- 그 코드나 배열을 가져오면 MIT 저작권·허가문을 유지해야 하므로 독립 구현 목표와 충돌한다.
- GeographicLib JS를 의존성 또는 번들 코드로 넣는다면 MIT/X11 고지를 NOTICE/third-party notices에 추가한다.
- 단순히 WGS84 좌표를 받고 이미 있는 지오데식 구현을 사용하지 않는다면 새 의존성은 필요 없다.

## 9. 책임 있게 주장할 수 없는 것

현재 자료만으로 다음을 제품 설명에 쓰면 안 된다.

- 신살이나 택일이 실제 사건의 성공률·이혼율·질병·수명에 인과효과가 있다는 주장
- “가족 전원의 사주를 합산한 정통 이사 택일”이라는 주장
- 건축 방향 금기를 일반 주소 이전 방향과 동일시하는 주장
- 모든 학파가 연지와 일지를 동시에 신살 앵커로 쓴다는 주장
- 천을귀인의 낮·밤·동하지 분할 중 하나가 유일 정답이라는 주장
- 여자의 생년으로 가족에게 해로운 혼인 달을 계산하는 기능
- 영인본 대조 전 음양불장 전사표를 정확한 정본이라고 하는 주장
- 길신·흉신 개수 또는 제품 점수를 운의 확률이라고 부르는 주장
