# Decision-quality readings

Use this for consequential choices and timing-fact requests.

## Define the real decision first

Compare actual demands, not labels. For each option identify the same axes, such as:

- sustained input and learning;
- output, evaluation, or delivery;
- closure and deadline;
- hierarchy, responsibility, and collaboration;
- delayed payoff, money, eligibility, and time;
- transition from preparation to a real role.

Refine these axes from the user's situation. Do not infer real-world requirements from Saju.

## Compare symmetrically

For each option:

1. name supporting validated evidence;
2. name counterevidence or another plausible reading;
3. distinguish chart-derived reasoning from external constraints;
4. use the same depth and criteria.

Never select a path from one element, one ten god, one symbolic star, or one profile candidate.

## Close the decision

Use one shape:

- clear preference;
- hybrid preference with a named base and lever;
- conditional parity with the real separator;
- insufficient separation and the missing real-world fact.

Use exactly one verdict-strength label:

- `분명`: several independent factors favor one route and counterevidence is weak;
- `중간`: one route is favored but a meaningful counterforce remains;
- `박빙`: the chart does not separate the routes without a non-Saju condition.

Do not use numerical fit scores or `중간 이상`.

State the switch condition: what real fact would legitimately reverse the verdict. Make clear that
money, qualification requirements, motivation, skill, eligibility, and available time do not come
from the chart.

## Advice must follow the mechanism

Generic advice does not become personal because it follows a Saju paragraph.

Weak:

- make a schedule;
- save money;
- do practice tests;
- do not give up.

Grounded shape:

> Because the validated mechanism repeatedly returns from output to more input, use an external
> deadline and finish one public artifact before adding another course.

Replace the mechanism with current validated evidence. Omit advice that fits almost every adult.

## Timing

Only present a timing layer the runtime actually calculated. Plugin 0.4 returns exact calendar
activation facts, not claim-gated timing interpretation. Show the requested range with exact
solar-term boundaries, pillars, ten gods, and the explicit approximate qualifier on luck-pillar
starts. Respect `luckPillarCount`; do not extrapolate unreturned decades. The returned luck-pillar
stem/branch ten gods are relational facts, not outcome predictions.

Do not select favorable or unfavorable periods, infer an activated function, or turn a timing
pillar into opportunity, burden, advice, or an event. If the user asks for such a prediction,
explain that the current timing branch is factual only and that a future version needs versioned
timing findings and local validation.

Do not:

- use January 1 as the Saju-year boundary;
- call a Gregorian month a Saju month;
- invent a precise transition that the runtime did not return;
- treat an arriving element as an automatic event;
- infer `합·충·형·해` or void branches as outcomes by themselves;
- let a monthly pillar override natal, decade, and annual context.

If the installed runtime does not support the requested timing layer, say so and give only the
validated natal analysis. Do not fall back to memory or an internet calculator.

## Final check

- Is the actual preferred route unmistakable?
- Did both options receive the same criteria?
- Is counterevidence visible?
- Is the switch condition explicit?
- Are external constraints separated from chart reasoning?
- Did every interpretive claim survive local validation?
- Does timing contain only calculated facts, with no host inference?
