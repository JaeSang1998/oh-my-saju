# Fluent Korean 전체 출력 점검

이 문서는 `fluent-korean` 스킬의 출력 규칙을 Oh My Saju에 그대로 적용하기 위한 필수
점검 기준이다. 한국어 해석, 궁합, timing 설명, 입력 안내, 오류 안내처럼 사용자가 읽는 모든
한국어 문장을 작성한 뒤, 검증 명령을 실행하기 전에 처음부터 끝까지 읽고 적용한다. 몇 개의
금지어만 확인하는 축약 절차로 바꾸지 않는다.

인용문, 코드, 코드 주석, JSON 키, finding ID, 이미 확정된 명식 용어에는 이 점검을 적용하지
않는다. 고유 명사와 기술 용어는 널리 쓰이는 번역어 또는 음차가 있으면 그것을 쓰고, 그렇지
않으면 원어를 보존한다. 외국어를 무조건 한국어로 바꾸지 않으며, 사용자의 단문·오타·속어를
그대로 따라 쓰지 않는다.

## 문장 단위

1. 독자가 빠진 말을 복원하지 않아도 되도록 의미 있는 문장 성분을 남긴다. 특히 `~의`를
   연달아 써서 주체·행동·조건을 흐리지 않는다. 예를 들어 `사본의 문구는 작업의 상황을`보다
   `사본에 기재된 문구는 작업이 진행되는 상황을`처럼 쓴다.
2. 제목과 목록 항목을 제외하면 명사구, 부사구, 연결어미로 끝내지 않는다. 서술어와 종결어미를
   갖춘 문장으로 끝맺는다.

## 구와 어휘

1. 관계를 밝혀야 할 때는 조사와 어미를 생략하지 않는다. 부사, 보조사, 선어말어미, 보조 용언을
   써서 문장 성분의 관계를 분명히 한다. 예를 들어 `이 결정은 이후 중요 정책이 갈리는 자리`
   대신 `이 결정은 이후 중요한 정책에도 지속적으로 영향을 미치기 때문에, 미리 신중하게
반영합니다`라고 쓴다.
2. 맥락에 맞는 한자어와 자연스러운 통사 구조를 함께 쓴다. `쓴 비용을 구하는 토큰 카운트
함수에 문제가 생기면`처럼 압축하지 말고, `지출한 비용을 추론하는 토큰 카운트 함수에 오류가
발생하면`처럼 관계를 드러낸다.
3. 일반적인 어휘가 필요한 자리에는 정착하지 않은 비유를 넣지 않는다. `분석의 흐름`보다
   `분석의 방향성`, `코드로 박는 자리`보다 `코드에 명시하는 상황`처럼 뜻을 직접 말한다.
4. 엠대시(`—`)는 앞뒤 문장의 관계를 지나치게 함축하므로 사용자용 한국어에는 쓰지 않는다.
   차트 근거와 풀이를 연결할 때는 콜론(`:`)이나 자연스러운 연결어미를 사용한다.

## 해석에 적용하는 방법

1. 명식 근거와 생활 풀이를 각각 읽은 뒤, 둘을 합친 최종 문장을 다시 읽는다. 누가 어떤
   상황에서 무엇을 하고 어떤 결과가 이어지는지가 분명해야 한다.
2. `구조가 작동합니다`, `통로가 열립니다`, `복원력으로 쓰입니다`, `현실적 결과로
흘려보냅니다`처럼 사람이 아닌 추상 명사를 주어로 삼는 번역투는 행동을 주어로 바꾼다.
3. 근거가 부족해도 의미가 완전한 문장을 쓰기 위해 새로운 사주 판단을 만들지 않는다. 근거가
   없는 항목은 빼고, 필요한 경우에만 해당 문장에 국소적인 조건을 붙인다.
4. 한국어 초안이 완성된 다음에만 claim 검증과 presentation 검증을 수행한다. 검증을 통과한
   Markdown은 뒤에서 다시 문체만 고치지 않는다. 문체 문제가 남으면 초안 단계로 돌아가
   고친 뒤 다시 검증한다.

한국어로 다른 에이전트에게 초안을 요청하거나 그 결과를 사용자에게 전달할 때도 같은 점검을
적용한다.
